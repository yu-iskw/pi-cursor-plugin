# Cursor plugin compatibility

pstack is the compatibility target. Installing it with `/cursor-plugin` exposes the same skills, agents, and rules Pi can run.

| Component                           | Current state                                                                                                                                                                              |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Cursor `.cursor-plugin/plugin.json` | Manifest detection, discovery, and Pi resource paths                                                                                                                                       |
| Agent Plugins `plugin.json`         | Manifest detection and discovery                                                                                                                                                           |
| Skills                              | Pi skill paths plus Cursor slash names such as `/poteto-mode`                                                                                                                              |
| Commands                            | Pi prompt templates                                                                                                                                                                        |
| Rules                               | `alwaysApply` rules are appended to the system prompt, including `~/.cursor/rules`                                                                                                         |
| Agents                              | `Task` spawns subagents. Concurrent writers get their own git worktrees                                                                                                                    |
| AskQuestion / TodoWrite             | `AskQuestion` (`prompt`, `{ id, label }` options, `allow_multiple`) and `TodoWrite` tools. The todo list stays on the system prompt and in the Pi widget, and the same session restores it |
| MCP servers                         | User, project, and enabled-plugin servers. Readonly children pass `--no-mcp`                                                                                                               |
| Hooks                               | Not executed. pstack does not ship any                                                                                                                                                     |
| Marketplace                         | GitHub repository aliases                                                                                                                                                                  |
| Updates                             | Re-clone source and record the resulting commit SHA                                                                                                                                        |

`/setup-pstack` still writes `~/.cursor/rules/pstack-models.mdc`. The extension reads that file on each run, so the model map applies inside Pi. Subagents are nested Pi processes with a persistent `--session-id`, so `Task` `resume` continues that Pi session. `poteto-agent` defaults to the background because its `is_background` frontmatter is true. `readonly` limits tools to `read,grep,find,ls` and passes `--no-mcp`. `auto` or `inherit-parent` runs the child on the parent Pi model and thinking level. An explicit slug replaces that model. `environment: "cloud"` starts a Cursor cloud agent through `@cursor/sdk` when `CURSOR_API_KEY` and a GitHub origin are present. `cloud_base_branch` is that agent's starting ref. A missing key or origin tells the caller to respawn with `environment: "local"`. A `bc-` id resumes the cloud agent. Readonly cloud runs do not open a pull request. A rejected model slug includes the closest slugs of that family from `pi --list-models` or `Cursor.models.list`. pstack families are `claude-*`, and `grok-*` together with `cursor-grok-*` and `composer-*`. A non-readonly agent registers MCP servers from `~/.cursor/mcp.json`, `<cwd>/.cursor/mcp.json`, and `mcpServers` files of plugins enabled in this manager. The same list is written to `~/.cursor/projects/<slug>/mcps` and added to the system prompt, which is the available-server map `/why` and `/reflect` read. Each connected server also gets a `tools/` descriptor so `/why` can classify it by tool name. Each run also names this workspace's `agent-transcripts` directory and the agent store. The Pi session is projected to `~/.cursor/projects/<slug>/agent-transcripts/<id>/<id>.jsonl`, and a local Task session is copied under that conversation's `subagents/` directory, which is the layout `/reflect`, `/recall`, and the other transcript skills read. A Task whose checkout is a git worktree still writes that transcript into the parent workspace's `agent-transcripts` directory. A readonly child passes `--no-mcp` and is told that MCP is disabled, so it does not treat the servers as missing. Cursor IDE plugin-cache proxies are left unregistered. A second concurrent writable local Task gets a git worktree at `~/.cursor/worktrees/<repo>/<task-id>` on branch `pstack/<task-id>`. Readonly Tasks and the first writer stay in the parent checkout. Resume reuses the recorded directory. Skills and rules with `paths` are inlined when the prompt names a matching file or an earlier read, edit, write, or grep touched one. A glob with no directory, such as `*.ts`, matches that name in any directory, and `{src,lib}` expands before matching. Project `.cursor/rules` are included only after the project is trusted. User rules, including the file written by `/setup-pstack`, stay in effect either way. Hooks are not executed.
